# iM Goal · climb

> iM금융그룹 공모전 시연용 프로토타입 (프론트엔드)
> 화면에 표시되는 모든 수치는 발표용 예시 데이터입니다.

**climb**은 "목표를 향한 여정(항로)"이라는 컨셉으로, 사용자가 재무 목표를 등록하면
AI가 페이스메이커처럼 소비를 실시간으로 감지하고, 이탈이 생기면 원인을 분석해
맞춤형 회복 미션을 제안하는 금융 건강 관리 앱입니다.

이 저장소는 현재 **프론트엔드(FE) 시연용 프로토타입**만 포함합니다.
백엔드 연동 없이, 화면 흐름과 로직을 실제 순서대로 체험할 수 있도록 만들어졌습니다.

## 2. 실행 방법

프로젝트 루트가 아니라 **`FE/` 폴더**에서 작업합니다.

```bash
cd FE
npm install      # 최초 1회 의존성 설치
npm run dev      # 개발 서버 실행 (Vite)
```

개발 서버가 뜨면 브라우저에서 안내된 주소(기본 http://localhost:5173)로 접속합니다.
앱은 데스크톱 화면 가운데에 **아이폰 프레임(PhoneFrame)** 형태로 렌더링됩니다.

기타 명령어:

```bash
npm run build    # 타입 체크(tsc) 후 프로덕션 빌드
npm run preview  # 빌드 결과 미리보기
npm run lint     # oxlint로 정적 검사
```

### 기술 스택

- **React 19** + **TypeScript**
- **Vite** (번들러 / 개발 서버)
- **React Router v7** (화면 라우팅)
- **Zustand** (전역 상태 관리)
- 스타일은 별도 CSS 프레임워크 없이 **인라인 스타일 + 디자인 토큰**(`src/styles/theme.ts`)으로 구성

## 3. 핵심 컨셉과 사용자 여정

"목표 = 목적지", "탑승권 발권 = 목표 등록", "항로 이탈 = 소비 과다", "난기류 = 지연"
처럼 **항공 여정 메타포**로 재무 목표 관리를 표현합니다.

전체 흐름은 다음 순서로 이어집니다.

```
상황 선택(페르소나)
      │
로그인 → 약관 동의 → 자산 연결 → 소득 확인
      │
목표 등록 (음성 / 타이핑) → AI 분석 → 플랜(탑승권) 발권
      │
홈 (여정 대시보드)
      │
실시간 소비 감지 → 이탈 알림 → 원인 분석
      │
맞춤 회복 미션 + iMKRW 보증금 예치
      │
3단계 회복 검증 → 경로 재계산 → FCPS(신용 궤적) 축적
```

핵심 차별 포인트:

1. **실시간 감지** — 결제 발생 60초 이내에 이탈 징후를 잡습니다. (사후 기록형 가계부와의 차이)
2. **원인 우선순위 분석** — 무엇이 목표 도착일을 얼마나 밀어냈는지 환산해서 보여줍니다.
3. **iMKRW 보증금형 미션** — 벌칙이 아니라 "약속 장치". 소액을 예치하고 수행하면 전액 반환.
4. **FCPS** — 신용 이력이 없어도 행동 궤적을 보완 지표로 축적합니다. (신용점수를 대체하지 않음)

## 4. 3가지 페르소나 (시나리오)

앱 진입 시 `PickerScreen`에서 상황(페르소나)을 하나 고르면, 그 사람의 앱이 열립니다.
페르소나별 수치/문구는 `FE/src/data/personas.ts`에 정의되어 있습니다.

| 키 | 페르소나 | 목표 | 대표 위험 상황 |
| --- | --- | --- | --- |
| **A** | 자립준비청년 (신파일러, 24세) | 전세보증금 3,000만원 (24개월) | 배달 지출 급증 |
| **B** | 소상공인 (취약차주, 41세) | 매출 회복 · 사업 안정화 (6개월) | 3개월 연속 매출 -18% |
| **C** | 리볼빙 청년 (직장인, 29세) | 비상자금 600만원 (15개월) | 카드 한도 소진율 82% |

각 페르소나는 **소득/자산/고정비, 하루 예산, 이탈 원인, 미션, 알림 문구, 계좌 구성**이
모두 별도로 정의되어 있어 시나리오마다 다른 데이터가 화면에 흐릅니다.

### UC(Use-Case) 워크스루

`FE/src/data/ucDefs.ts`에는 페르소나별 UC 시연 화면(u11~u36, 총 18개)이 정의되어 있습니다.
- **UC-01 (A)**: 목표 등록 → 감지 → 원인 → 미션 → 보증금 → 회복 검증 → FCPS
- **UC-02 (B)**: 매출 모니터링 → 위험 등급 판정 → 사업자 유형 판별 → 정책 연결 → 회복미션
- **UC-03 (C)**: 한도 감지 → 리볼빙 원인 → 한도 낮추기 미션 → 회복 검증 → 정책상품 → FCPS 추이

**브랜드 컬러**

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `color.mint` | `#00C7A9` | iM 민트 (메인 브랜드) |
| `color.lime` | `#E2F15E` | 라임 액센트 |
| `color.ink` / `navy` | `#16191C` | 잉크 블랙 (텍스트/배경) |
| `color.sky` | `#7DB5FF` | 스카이 (보조) |
| `color.coral` | `#FF7A5C` | 경고/위험 강조 |
| `color.gold` | `#C9A052` | 등급(골드) 표현 |

- **폰트**: Noto Sans KR (`index.html`에서 Google Fonts로 로드)
- **radius / font** 등 부가 토큰도 `theme.ts`에 정의
- **모티프**: 천공(항공) 탑승권 티켓, 마스코트 **단디(dandi)** · **똑디(ddokdi)**

## 7. 데이터 모델과 앱 상태

### 전역 상태 (Zustand)

`FE/src/store/appStore.ts`가 세션 전체의 시뮬레이션 상태를 관리합니다.
타입은 `FE/src/types.ts`의 `AppState`에 정의되어 있습니다. 주요 필드:

| 필드 | 의미 |
| --- | --- |
| `persona` | 현재 선택된 페르소나 (`A`/`B`/`C`) |
| `hasGoal` | 목표 등록 여부 |
| `spent` | 오늘 소비 금액 (이탈 판정에 사용) |
| `alertOn` | 이탈 알림 표시 여부 |
| `consents` | 동의 항목 배열 |
| `missionOn` / `recovered` | 회복 미션 진행/완료 상태 |
| `fueled` | 목표 달성(연료 충전) 상태 |
| `incomeMonthly` / `incomeAssets` / `incomeFixed` | 소득/자산/고정비 |

`FE/src/viewmodel/useJourney.ts`는 여러 화면(홈/상세/급여/토큰)이 **같은 숫자**를 쓰도록
공통 계산(남은 예산, 이탈 여부, 등급, 도착 예정일 등)을 한 곳에서 파생합니다.

## 8. 백엔드 연동 관점

현재 프로토타입은 **모든 데이터가 프론트엔드에 하드코딩**되어 있고, 실제 API 호출이 없습니다.
발표/시연용으로 화면의 수치는 미리 정해진 예시 값입니다. 향후 백엔드 연동 시 참고할 지점:

- **데이터 소스 위치**: `FE/src/data/*.ts` 의 상수들이 실제 API 응답으로 대체될 대상입니다.
  (페르소나 프로필, 계좌/거래 내역, 미션, 원인 분석, 소비 카테고리 등)
- **상태 관리 위치**: `appStore.ts`의 액션들(예: `triggerPersonaAlert`, `completeRecovery`,
  `simulateOverspend`)은 지금은 로컬 시뮬레이션입니다. 실제로는
  실시간 거래 감지 / 미션 판정 / 회복 검증 결과를 서버에서 받아 상태를 갱신하는 형태가 됩니다.
- **연동 후보 도메인**: 마이데이터(계좌·카드·매출), 실시간 결제 감지 이벤트,
  원인 분석 스코어링, 미션 추천, iMKRW 보증금 스마트계약, FCPS 궤적 산출.
- 인증/로그인, 동의(consent) 항목도 현재는 UI 흐름만 구현되어 있어 실제 인증 연동이 필요합니다.

### 보증금 추천 데모 (`/token`)

- 미션 상세에서 기간을 선택하고 보증금 화면으로 이동하면 일일 예산, 선택 기간, 오늘 초과 지출, 월소득·고정비·목표 저축액, 지갑 잔액과 최근 미션 결과로 추천액을 계산합니다.
- `viewmodel/depositRecommendation.ts`의 설명 가능한 데모 정책입니다. 실제 AI 모델/API나 검증된 최적화 공식은 아직 연결하지 않았습니다.
- 기준액 = (일일 예산 × 미션 일수 × 10% + min(오늘 초과 지출, 일일 예산) × 25%). 최근 미션이 실패·포기이면 기준액에 75%를 적용합니다.
- 상한 = min(월소득에서 고정비·목표 월저축을 뺀 여유의 10%, 지갑 잔액의 60%, 남은 목표 금액, 50,000원). 기준액과 상한 중 작은 값을 1,000원 단위로 내림합니다. 추천액이 0이면 보증금 없는 기존 미션 경로를 안내합니다.
- 추천 이유 및 펼쳐보는 계산 근거를 확인할 수 있습니다. `바꾸기`를 누르면 1,000~50,000원 슬라이더가 열립니다. 취소는 원래 선택으로, 추천 금액으로 맞추기는 AI 제안 금액으로 돌아갑니다.
- 슬라이더 조정·적용은 화면의 선택만 바꾸며 지갑·예치 상태는 변경하지 않습니다. 최종 동의 버튼에서만 기존 `startMission`을 호출합니다. 잔액 초과 금액을 직접 고르면 자동충전 예정액을 미리 고지합니다.
- 이미 보증금 미션이 진행 중이면 추가 예치 대신 진행 중인 미션을 안내합니다. 성공·실패·포기 시 전액 반환하는 기존 데모 정책은 유지합니다. 보증금을 늘려도 목표 달성일·수익을 보장하지 않습니다.


### 회복 미션 시연 흐름

- 소비 위험 알림 → 회복 미션에서 추천 사유·완료 기준·기간별 절약 예상액 확인 → 보증금 선택 또는 보증금 없이 시작.
- 진행 화면은 선택한 기간과 실제 시작일을 사용합니다. 성공/실패/중단 시나리오를 선택하면 `/verify`에서 목데이터 판정 근거를 먼저 확인합니다.
- 판정 확정 후에만 보증금 반환·FCPS 기록을 1회 처리합니다. `/release` 직접 방문이나 중복 확정은 추가 정산을 만들지 않습니다.
- 성공 결과와 홈은 같은 시작 시점의 계획을 사용합니다. 절약 예상액 ÷ (월 목표 저축액 ÷ 30)을 일 단위로 내림하고 기존 지연일 이내로 제한합니다. 이 예상치는 실제 거래 조회·저축 이체 결과가 아니며 보증금 반환액을 포함하지 않습니다.
- 실패/중단 결과에서 7일 미션으로 다시 계획할 수 있습니다. 새 시작을 확정하기 전에는 돈이 움직이지 않습니다.
- 검증: `cd FE` 후 `node scripts/test-recovery.cjs`, `npm run build`.


### 똑디 공통 챗봇

모든 화면 오른쪽 아래의 똑디 버튼으로 열 수 있습니다. 화면별 추천 질문, 현재 상태를 읽는 데모 답변, 관련 화면 이동을 제공합니다. 대화는 화면 이동·닫기 후에도 유지하며 상황 A/B/C별로 분리합니다. 새로고침하면 초기화되며 각 상황의 최근 80개 메시지를 유지합니다. 외부 AI API는 연결하지 않았고 답변은 로컬 규칙 기반입니다. 챗봇은 예치·정산·미션 시작을 실행하지 않습니다. Esc 또는 배경 클릭으로 닫고, 대화 지우기는 현재 상황의 대화만 지웁니다.
