# iM Goal · climb

금융 목표 설정부터 소비 확인, 행동 미션, 재무 변화 관찰까지 연결한 프론트엔드 프로토타입입니다. React 19 · TypeScript · Vite · React Router · Zustand를 사용합니다.

현재 구현은 입력값과 저장된 기록에 반응하는 로컬 앱입니다. 은행 거래 조회, 실제 이체, 실시간 위험 탐지, LLM·RAG, 기관 접수·심사는 연결하지 않았습니다. 초기 거래·과거 마일리지는 예시이며, 후속 관찰 화면에는 기간 경과 가정을 표시합니다.

## 실행과 검증

프로젝트 루트에서 실행합니다.

~~~sh
npm --prefix FE install
npm --prefix FE run dev
npm --prefix FE run build
npm --prefix FE run lint
npm --prefix FE test
~~~

Vite가 안내한 주소를 엽니다. 개발·미리보기 서버는 깊은 화면 경로도 처리합니다. 별도 정적 호스팅에서는 모든 앱 경로를 index.html로 보내는 SPA fallback이 필요합니다.

- [데모 진행 가이드](DEMO_GUIDE.md): 정상·위험·성공·재시도·지원·분배·복원 흐름
- [구현 명세 및 연동 경계](IMPLEMENTATION_STATUS.md): 현재 기능, 산식, 저장·판정 규칙, 향후 API 작업
- [디자인 스킬](디자인스킬.md), [UI·UX 원칙](UI-UX%20디자인%20원칙.md): 기존 민트·라임·중립색과 공통 버튼·여백 규격

## 사용자 흐름

1. 상황 선택 → iM뱅크 홈 → CLiMB 배너 → 마이데이터 동의 → 연결 → 소득 확인 → 빈 홈
2. 미리 작성한 목표 대화 진행 → 리포트 확인·수정 → 발권 → 홈
3. 홈 트리거 → 원인 확인 → 미션·기간·선택 보증금 확인 → 시작
4. 행동 결과 판정 → 보증금 반환과 FCPS 기록 → 재무 변화 확인 → 4주 유지 확인
5. 실패·중단이면 어려웠던 이유 선택 → 행동·성공 기준을 조정한 미션 재추천
6. 필요하면 지원 안내 → 준비 목록 → 공식 기관에서 상담·신청 이어가기
7. 분배 비율 저장 → 반영 금액 확인 → 앱 내 분배 기록 → 3·6개월 금융 습관 확인

똑디 챗봇은 하단 탭이 있는 화면에서만 표시합니다. 초기 설정·로딩·뒤로가기로 나오는 상세 화면에는 표시하지 않습니다. 로컬 문답 규칙으로 현재 목표·예산·미션을 설명하며, 자유 대화 LLM은 연결하지 않았습니다. 목표 대화는 feat/기능의 미리 작성한 시나리오를 사용합니다. 채팅 옆 마이크는 듣는 표시 후 준비된 문장을 채우는 연출이며 실제 녹음·권한 요청은 하지 않습니다.

## 계산과 기록의 기준

- 소비 기준 월: 2026년 7월, 기준일: 7월 31일. A 배달·C 카드 트리거는 같은 거래 장부에 한 건을 추가합니다. B는 소비가 아니라 월매출 감소입니다. 같은 위험 이벤트를 반복 눌러 거래·매출 변동을 중복 반영하지 않습니다.
- 목표·거래·예산: appStore와 financePlan을 홈·리포트·소비분석·달력이 공유합니다. 기본 월 필요 저축은 (목표−모아둔 돈)/남은 개월입니다. 고정비·상환액·소비예산·지갑 배정액을 제외한 여력으로 예상일을 계산합니다.
- 분배 비율은 고정비·상환액을 제외한 금액의 목표 저축 / iMKRW / 생활비 비율입니다. 합계 100%를 유지하며 원 단위 잔여액·목표 초과분은 생활비로 보냅니다. 같은 상황·같은 달의 분배는 한 번만 기록합니다.
- 기간은 7/14/21/28일 중 선택합니다. 시작 시 행동·성공 기준·예상 절약액을 고정하며, 실패 이유 변경으로 과거 약정이 바뀌지 않습니다.
- 행동 성공은 FCPS +18, 실패 −8, 중단 −5입니다. 보증금은 모든 결과에서 전액 반환합니다. 이후 회복 관찰은 추가 적립·반환·실제 저축 이체를 만들지 않습니다.
- 재무 개선은 행동 성공과 별개입니다. 7일 후 변화, 이후 4주 유지 기록을 가정해 확인합니다. 자료 부족은 판단 보류, 재악화는 추가 조정으로 분기합니다.
- 금융 습관 화면은 저장된 기록과 초기 예시 이력을 집계합니다. 자료가 없는 날짜나 달을 예산 준수·0원 소비·실패로 간주하지 않습니다. FCPS는 공식 신용점수가 아닙니다.

## 저장과 초기화

브라우저 localStorage의 im-goal-state-v1에 현재 상황의 목표·거래·예산·분배·미션·회복·지원 준비 기록을 저장합니다. 서버나 다른 기기와 동기화하지 않습니다. 챗봇 대화와 열려 있는 입력 초안은 새로고침 시 초기화됩니다.

- 새로고침: 현재 화면과 저장한 기록을 이어봅니다.
- 상황 바꾸기 → 현재 기록 이어보기: 초기화하지 않고 복귀합니다.
- 상황 카드를 새로 선택: 새 시나리오로 초기화합니다. 이전 상황별 저장 슬롯은 없습니다.
- 마이페이지 → 기기 기록 관리: 초기화 내용을 확인하고 기록을 초기 상태로 되돌립니다.
- 저장소 사용이 제한되면 이번 실행 중에만 유지될 수 있으며 기기 기록 관리에서 오류 안내를 확인합니다.

## 폴더 구조

- FE/src/store: 공통 상태, 저장소, 소비 화면의 선택 월
- FE/src/viewmodel: 목표 계산, 분배 계산, 미션 추천·회복 판정, 금융 습관 집계, 챗봇
- FE/src/data: 초기 거래·과거 이력, 상황별 기본값, 공식 지원 경로
- FE/src/screens 및 components: 화면과 공통 UI
- FE/src/styles: 색상·폰트·간격·버튼 토큰과 화면 스타일
- FE/scripts: 계산·상태 전이·복원 회귀 테스트
